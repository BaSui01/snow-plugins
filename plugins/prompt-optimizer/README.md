# 提示词优化

为 Snow App 聊天草稿改善表达、整理任务或去除重复内容。**右侧面板负责配置，输入栏魔杖负责执行**；生成后可回填、预览应用和还原，发送始终由您决定。

## 安装与宿主要求

在 Snow App 插件管理页点击「从目录安装」，从您下载或克隆仓库的实际位置选择 `plugins/prompt-optimizer`，确认目录内直接包含 `plugin.json`。插件标识为 `com.snow.prompt-optimizer`，清单版本为 `1.2.0`。

需要 **Snow App v0.4.16 或更新版本**提供专用提示词优化接口、输入栏动作和安全草稿回填。配套改动已通过 [PR #179](https://github.com/MayDay-wpf/snow-app/pull/179 "提示词优化所需宿主增强已合并") 合并，并进入正式版 v0.4.16；v0.4.15 不包含该能力。仅安装插件或刷新旧应用不能补齐这些能力。

**1.2.0 版本：运行中安全优化、含图草稿视觉指引增强、独立默认隐藏齿轮及持久显示开关需配套 Snow App 宿主构建，尚无已确认正式发行版本，UI/重启未验收。** 「执行期间只显示转圈」同样是宿主通用改动，旧宿主仍会显示状态文字。本地宿主源码版本号不等同已发布能力。旧宿主可能继续禁用运行中优化、忽略齿轮声明并显示齿轮；变更与验证边界见 [发布说明](RELEASE.md)。

如果从旧宿主升级后看不到输入栏入口，请在支持这些能力的新构建中「重新读取清单」或重新安装插件。重复安装会更新已安装副本并保留启用状态和已保存偏好；修改源码目录不会自动更新已安装副本。

## 首次配置

1. 从顶栏加号菜单的插件分组或右侧插件入口打开「优化提示词配置」。**魔杖默认显示，输入栏齿轮默认隐藏，不代表插件被禁用。**
2. 可用「在输入栏显示优化配置齿轮」开关显示齿轮。该偏好立即单独持久化，输入栏同步更新、重启后保留；点击齿轮只打开本插件配置，不触发优化、不保存未保存规则、不取消正在进行的优化。
3. 选择策略，按需修改优化规则、上下文、服务与模型，点击「保存配置」。看到保存成功后，下次点击魔杖即可使用。

**未保存的编辑不会影响执行。**「查看优化规则」预览的是当前编辑内容，输入栏执行使用的是最新已保存配置。配置由宿主保存，不按项目或会话分开。

### 策略怎么选

四种策略**不是替换**您写的优化提示词，而是叠加。实际发给模型的规则按固定顺序拼接：

1. **宿主固定底线**（不可覆盖）：只改写、不执行、不调用工具、不回答草稿中的问题、只输出纯文本
2. **公共偏好说明**：策略定编辑重点、长度定详略、表达定格式；三者都不得先于「保留有效约束与不确定性」
3. **您填写的优化提示词**（最多 7000 码点）
4. **所选策略**一句话
5. **所选长度**一句话
6. **所选表达结构**一句话

所以改策略只替换第 4 步那一句，其余全部保留。四条策略注入的实际语义差异：

| 策略 | 注入的核心指令 | 对结果的典型影响 | 与长度/结构的相互作用 |
| --- | --- | --- | --- |
| 保真增强（默认） | 谨慎提升清晰度；**仅**在草稿或上下文有依据时澄清歧义，否则原样保留；保留全部意图、事实、约束与不确定性；绝不新增要求 | 改动幅度最小，措辞更顺、指代更明确，内容几乎不变 | 与任何长度/结构都兼容，是最安全的组合 |
| 结构化任务 | 把**已有**的目标、背景、约束、输出要求整理成连贯顺序；**服从表达结构偏好**，不强行加标题；缺信息就省略而非编造 | 信息顺序变清晰、层级分明，便于模型按序执行 | **明确让位给表达结构**：选「自然语言段落」时不会产生标题；选「分节/列点」时才分节。与「尽量精简」并用会压缩过渡语 |
| 精简去冗余 | 删除重复与冗长措辞，但保留每条有效要求、限定条件、事实与不确定性 | 字数明显下降，信息密度上升 | 与「适度展开」**直接冲突**：策略要删冗余、长度要展开说明，实际结果是「只删不增」，净长度基本不变 |
| 自定义策略 | 仅声明「不加预设策略，按您的优化提示词改写」 | 完全由您那份规则决定风格，插件不施加额外编辑倾向 | 长度与表达结构**仍然生效**——被中性的只有策略这一项 |

三项长度偏好的差异：

| 长度 | 注入的核心指令 | 注意 |
| --- | --- | --- |
| 尽量保持原长度 | 尽量与草稿相当；**绝不**为了凑长度丢弃有效约束 | 默认值，最不容易误伤 |
| 适度展开已有信息 | 只能把**已有**的意图或约束解释得更清楚；不加事实、示例、要求、假设 | 与「精简去冗余」策略并用时几乎被抵消 |
| 尽量精简 | 用能保住完整意图与全部有效约束的最短措辞 | 与「保真增强」策略并用最稳 |

两种表达结构的差异：

| 结构 | 注入的核心指令 | 注意 |
| --- | --- | --- |
| 自然语言段落 | 清晰的段落，不要多余的模板标题 | 「结构化任务」策略下仍不会加标题 |
| 按已有信息分节 / 列点 | 只对**实际存在**的信息分节或列点；空章节、无依据章节一律省略 | 想得到标题就必须选这一项 |

**推荐组合**：日常用「保真增强 + 尽量保持原长度 + 自然语言段落」；要交付给模型执行的复杂任务用「结构化任务 + 尽量保持原长度 + 按已有信息分节」；嫌啰嗦用「精简去冗余 + 尽量精简」；已有成熟写法就用「自定义策略」。

「优化提示词」是指导优化器的规则，**不是待发送的聊天草稿**。它最多 7000 Unicode 码点，与策略、长度、结构合并后的完整规则最多 8000 码点——也就是说，提示词写得越满，留给策略偏好的空间越小，超限时面板会直接报「规则过长」并拒绝保存。出厂默认值是一份分节规则（中文约 530 码点，英文约 1600 码点），已包含指代解释、保留项清单与输出约束；合并后的完整规则中文约 1300 码点、英文约 2400 码点，附带图片时再增加约 380 码点，距离 8000 上限仍有充裕空间。点「恢复默认配置」会回到这份默认值。

「恢复默认配置」需要再次确认并保存：重置规则、策略、上下文与回填偏好，保留当前有效服务和模型，不修改聊天草稿。

### 上下文与模型

- 默认结合当前会话最近 **3 轮文本**，可选 1–10 轮或「仅优化草稿，不带历史」。新会话没有历史时只处理草稿。
- 该卡片下方有**实时提示**，说明本次是否真的会带入历史，共四种状态：已绑定且有消息时显示将带入的轮数与当前会话真实消息条数；已绑定但会话内还没有消息、以及新会话时，用琥珀色明确提示本次不带入（发送第一条消息后即会带入）；策略选「仅优化草稿」时提示不带历史。切换会话时提示实时刷新。
- 初次配置、尚无明确服务与模型选择时，面板默认选中宿主**唯一活动服务的基础模型**；这是待保存选择，需点击「保存配置」才用于执行。
- 可以手动选择服务及其已配置基础模型或高级模型；相同模型去重，不提供视觉模型或手填模型入口。
- 切换服务时选中该服务的基础模型；没有基础模型则留空，需手动选择有效模型。无法确定唯一活动服务或基础模型时会提示，不自动改用高级模型。
- 已保存的明确选择不会跟随活动服务变化。每次执行都会重新读取服务并校验所选模型；选择失效或读取失败时停止并报错，不静默回退其他服务。
- 在宿主修改服务或模型后，可点击「重新读取服务」刷新列表；正在编辑的其他配置不会丢失。重新选择后仍需保存。

## 日常使用

1. 在聊天输入框写好纯文本草稿。
2. 点击输入工具栏的**魔杖**（模型选择器左侧），无需打开配置面板。点击即按已保存配置执行，不另弹费用或隐私确认窗。
3. 生成期间原稿保持不变；**输入栏只显示转圈，不显示任何文字**，再次点击魔杖可取消本次优化，不停止普通聊天。
4. 默认成功后自动回填，并提供「还原」。若关闭「成功后自动回填输入框」，先在输入区小预览检查，再点击「应用」。
5. 检查结果后自行发送。**插件不自动发送消息。**

附件与引用保留，在回填时自动合并保留原图与原文件。输入框附带图片或截图时，优化器会在改写指令中动态强化视觉引用的保留与明确化，确保改写后的提示词清晰引导模型审阅图片，不误删对视觉线索的引用。生成期间编辑草稿或实际发送导致草稿变化、被清空时，旧结果不会覆盖新内容。编辑回填后的草稿、切换项目/真实或 pending 会话、进入不可编辑压缩、插件更新或禁用等会使旧应用或还原操作失效；应用与还原令牌单次使用、5 分钟有效。主 Agent 实时回复或运行/停止状态本身不会使令牌失效。再次优化会以当时草稿为新原文，不能再还原到上次原稿；打开配置不会触发或取消优化。

**Agent 运行期间仍可手动优化可编辑草稿**，主 Agent 回复变化不会取消优化。优化结果仍由您自行发送，通过宿主既有排队或 steer 策略处理；插件不改队列条目、不把优化规则写入聊天，也不新增自动优化模式。空草稿、只有附件、API 不可用/加载中或压缩使输入不可编辑时不能执行优化；停止中按真实输入可编辑契约允许优化。配置面板不受草稿或 API 可用状态限制。

## 隐私、费用与边界

- **点击魔杖会把草稿及所选会话上下文发送至所选模型服务，可能产生 API 费用。**处理敏感文本时请先确认服务可信，并考虑选择「仅优化草稿」。优化规则也会随请求发送，请勿在其中填写密钥或秘密。
- 打开面板、读取服务和保存配置不调用 AI。插件不读取 API 密钥、附件内容、文件数据、图片像素、思维链或工具结果。草稿中附带图片时，优化器通过标签感知视觉输入的存在，并在改写规则中自动增强对视觉引用的保护。
- 插件仅持久化配置，不持久化草稿、历史、结果或应用与还原令牌。模型服务自身的数据保留政策需另行确认。
- 优化只改写文本，不执行草稿中的任务或工具，也不把优化请求保存为普通会话消息。若要改写用于网络搜索的提示词，可将文本放入草稿；这不会执行搜索或修改宿主搜索配置。
- 宿主规则要求只改写、不执行、不编造，但不能保证所有模型输出正确。请在发送前检查事实、约束和语气。
- 缺少宿主能力时不通过聊天 DOM 或普通聊天替代执行。

## 开发参考与许可证

源码使用 TypeScript，目录 `src/` 为唯一可编辑来源：`preferences.ts`（偏好与规则）、`profiles.ts`（服务读取与校验）、`action.ts`（输入栏动作）、`panel.tsx`（配置面板）、`jsx.ts`（复用宿主 React 的 JSX 工厂）。宿主以 ESM 动态导入 `plugin.json` 的 `entry`，运行时无法解析相对导入，因此必须打包成单个 `index.js`：

```sh
cd plugins/prompt-optimizer
npm ci
npm run check   # tsc --noEmit + 校验 index.js 与 src/ 一致
npm run build   # 重新生成 index.js
```

**不要直接编辑 `index.js`**：它是构建产物，CI 会运行 `npm run check` 校验其与 `src/` 一致。`src/`、`scripts/`、`package.json` 等开发文件不会进入发布安装包。

本插件采用 ESM；输入栏动作使用 `optimizeDraft`，生成由 `api.ai.optimizePrompt` 承接，回填与还原通过宿主安全草稿动作完成。接口与生命周期契约请查阅 Snow App 内置文档「插件开发与安装」及「插件元数据域参考」，不要以本文代替接口文档。
